# lgd-engine 契约测试与验证（2026-11-18）

## 起因

lgd-engine 已有 9 步 CI（gate_bot、生态自测、demo2、MCP smoke、OpenAPI、红队自检、安全扫描、SSE），但全部是"跑脚本看退出码"。其中 MCP smoke 只能证明**线是通的**（工具能列、判定能出、越权能拒），不能证明**律是成立的**（无证据的 go 会不会被降级、判定器崩了会不会伪装成合法拒绝、用法错误会不会冒充 REJECT）。两者差一层：单元级断言。

## 新增

`tests/test_contract.py`，13 条断言，纯标准库，无第三方依赖：

| 组 | 断言 | 钉住的行为 |
|---|---|---|
| 三律 | 5 | 空引擎→hold（不默认放行）；critical→reject 且记 L3；go 无证据→hold 且记 L2；go 有证据→go；判定器崩溃→reject **且** errors 非空 |
| CLI 契约 | 4 | 用法错误退出 64（不是 2）；`--all` 全部命中预期；同一用例两次输出逐字节相同；退出码与判定一致（0=go） |
| RBAC | 4 | 未声明角色→-32003；未知工具→-32003；只读角色可跑 judge_change；**角色表缺口被显式钉住** |

CI：`.github/workflows/gate.yml` 新增一步 `python -m unittest discover -s tests -v`，紧接 MCP smoke 之后。

## 跑出来的真实结果

```
Ran 13 tests in 1.072s
OK
```

## 顺带查出的一个真缺口

`ROLE_TOOLS` 里 `reviewer` 与 `read-only` 的工具集**完全相同**，且没有任何写/审批类工具存在。也就是说：权限分层目前只是表结构，没有实际分离能力——一个声明为 reviewer 的调用方，能做的事和只读调用方一模一样。

这条我没有"顺手改好"，而是**写成断言钉住**（`test_role_table_gap_is_pinned`，注释里写明"这是已知限制，不是特性"）。理由：改权限语义是架构决策，不是测试能替作者拍板的事；钉住的目的是让将来任何一次改动都必须显式面对它，而不是悄悄漂移。

## 怎么复跑

```bash
cd <lgd-engine>
python -m unittest discover -s tests -v
```

## 边界（没做的事）

- **没有推送仓库**。改的是本地工作副本，`gate.yml` 的这一步需要在推送后才会在 GitHub 上真正执行。推送属对外动作，等明确授权。
- 没有跑 TypeScript 子项目 `lgd-engine-ts` 的测试（本轮只覆盖 Python 判定核心）。
- 没有改任何判定逻辑，只加断言。若这些断言本身写错了期望，那属于我的理解问题，而不是引擎的问题——这一点请按可复跑结果自行核验。
