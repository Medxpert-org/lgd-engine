# 第三个判定器：PCCP 变更范围（2026-11-18）

## 一句话

回答一个问题：**这次变更能不能走已授权的 PCCP，还是必须单独报批？** 全部规则离线、确定性、可逐条引用法规，不含任何 LLM 调用。

## 法规依据（全部为公开文本）

| 依据 | 内容 | 本判定器用它做什么 |
|---|---|---|
| FD&C Act §515C（FDORA，2022-12-29 加入） | 与已授权 PCCP **一致**的变更，不需要新的 510(k) / PMA 补充 | 划出"有护盾"与"没护盾"的分界 |
| 21 CFR 892.2055（2026-06-17 最终令，首个必须带 PCCP 的器械类型） | 特殊控制要求：计划化修改与方法学、风险分析、标签**含版本历史**、量化验收标准被满足 | 把"验收标准未达标""标签无版本历史"升为硬条件 |
| FDA 最终指南《PCCP for AI-Enabled Device Software Functions》（2025-08） | **改变预期用途或基本主张的变更被排除在 PCCP 之外**；持续学习/自动更新建议走 Q-Sub | 把"想用 PCCP 覆盖新适应症"判为不合格路径 |
| 同一指南关于 UDI | 版本变化应产生新 UDI | 让"版本变了、UDI 没变"进入 hold |

## 规则表（每条都可被监管同事单独质疑）

### 一票否决（critical → reject）

| 规则 | 触发条件 | 为什么是 reject 而不是 hold |
|---|---|---|
| P-CRIT-01 claimed-coverage-without-pccp | 没有已授权 PCCP，却按"PCCP 覆盖"实施 | 无护盾而宣称有护盾 = 未获批修改 |
| P-CRIT-02 intended-use-change | 改变预期用途/基本主张 | 指南明确排除，重报计划也绕不过去 |
| P-CRIT-03 acceptance-criteria-not-met | 量化验收标准未达标 | 特殊控制有约束力，不达标即不得按计划放行 |

### 升级（major → hold）

| 规则 | 触发条件 |
|---|---|
| P-MAJ-01 outside-pccp-scope | 不在授权范围内 |
| P-MAJ-02 modification-class-not-described | 修改类别未在 PCCP 文本中描述 |
| P-MAJ-03 validation-not-documented | 本次更新的 V&V 未归档 |
| P-MAJ-04 acceptance-criteria-unproven | 验收标准**没测**（不是失败，是没数据） |
| P-MAJ-05 labeling-version-history-missing | 标签无版本历史 |
| P-MAJ-06 udi-not-regenerated | 版本变化未产生新 UDI |
| P-MAJ-07 evidence-insufficient | 证据包缺失/待补 |
| P-MAJ-08 pccp-status-unknown | 是否已授权 PCCP 未说明 |
| P-MAJ-09 not-fda-jurisdiction | 非 FDA 辖区（PCCP 是美国机制） |
| P-MAJ-10 unknown-change-type | 变更类型不在可分类集合内 |
| P-MAJ-11 unknown-evidence-sufficiency | 证据充分性取值不可分类 |

### 放行（green）

| 规则 | 触发条件 |
|---|---|
| P-MIN-01 covered-retrain | 已授权 + 范围内 + 不改用途 + 验收达标 + 有证据 |

## 设计原则（与前两个判定器一致）

1. **未证明 ≠ 通过**：缺字段一律 hold，不给"默认安全"。
2. **未知 ≠ 通过**：不在枚举内的取值一律 hold（这条是被红队打出来才补的）。
3. **critical 不许降级**：任何后续规则都不得把 reject 改写成 hold。
4. **空证据不是证据**：`{"kind":"","ref":"   "}` 不满足 L2，go 会被降为 hold。
5. **跨辖区不外推**：非 FDA 直接 hold，不假装懂 EU MDR / NMPA 的变更门槛。
